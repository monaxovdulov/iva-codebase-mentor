# Iva Codebase Mentor

Публичный составной скилл для Iva, который помогает последовательно изучать кодовую базу и строить её персональную карту знаний.

## Идея

Пользователь подключает репозиторий и получает по расписанию или по запросу компактные учебные карточки. Скилл исследует код через AST, показывает связи между его частями, объясняет синтаксис и помогает понять возможные причины архитектурных решений.

Каждый следующий запуск учитывает уже изученные темы, изменения в репозитории и текущий уровень понимания пользователя.

## Возможности

- исследование символов, вызовов, реализаций, зависимостей и тестов через `ast-index`;
- ежедневная карточка по расписанию Iva;
- карточка по запросу о конкретном файле, символе, модуле или потоке исполнения;
- постепенное построение связанной карты кодовой базы;
- объяснение синтаксиса с учётом знаний пользователя;
- адаптивный выбор следующей темы без ненужных повторов;
- вопросы для самопроверки и возврат к плохо усвоенным темам;
- отслеживание изменений между состояниями репозитория;
- отправка результата как Telegram rich message средствами Iva.

## Состав карточки

Карточка должна содержать только полезный для выбранной темы материал:

- название и роль элемента в системе;
- расположение в репозитории и текущий commit;
- небольшой фрагмент кода;
- основные входящие и исходящие связи;
- объяснение важного синтаксиса;
- подтверждённые факты о поведении;
- возможные причины выбранного решения;
- короткий вопрос для закрепления;
- ссылки на связанные карточки карты.

Факты из кода, документированные решения и предположения модели должны быть явно разделены. Предположение нельзя выдавать за намерение автора.

## Режимы

- `daily` — выбрать следующую тему и прислать карточку;
- `explain` — объяснить выбранный участок кода;
- `trace` — проследить поток исполнения;
- `map` — исследовать модуль и дополнить карту связей;
- `review` — проверить и закрепить ранее изученное;
- `changes` — объяснить значимые изменения после предыдущего анализа.

## Архитектура

```text
Планировщик Iva или запрос пользователя
                ↓
        главный скилл-оркестратор
                ↓
     память + состояние репозитория
                ↓
    ast-index → выбор темы → объяснение
                ↓
       обновление карты и прогресса
                ↓
          rich message в Telegram
```

Скилл отвечает за исследование, обучение и обновление памяти. Расписание, часовой пояс, запуск и доставка остаются ответственностью Iva.

## Память

Для каждого репозитория создаётся отдельное пространство памяти. Репозитории идентифицируются стабильным `repository_id` и не смешиваются между собой.

В памяти хранятся:

- карта модулей, символов и связей;
- изученные и ещё не изученные темы;
- уровень понимания понятий;
- история карточек и ответов пользователя;
- очередь повторения;
- последний обработанный commit;
- состояние и результат последнего запуска.

Смысловые знания хранятся в Markdown внутри vault. Техническое состояние запуска хранится отдельно в версионируемом формате. Поиск всегда ограничивается пространством текущего репозитория.

## Композиция

Главный скилл координирует несколько процедур:

- исследовать кодовую базу;
- выбрать следующую тему;
- объяснить код и синтаксис;
- обновить карту;
- обновить учебный профиль;
- подготовить и отправить rich-карточку.

Процедуры с рассуждением оформляются как инструкции скилла. Индексация, идентификаторы, блокировки, проверка состояния и запись прогресса реализуются детерминированными скриптами.

## Требования

- исходный код по умолчанию только читается;
- приватный код и его фрагменты не отправляются во внешние сервисы без явного разрешения;
- каждый факт должен иметь ссылку на файл, символ и commit;
- повторный запуск не должен дублировать карточку или прогресс;
- незавершённый запуск не должен отмечаться успешным;
- изменения кода должны обновлять устаревшие элементы карты;
- отсутствие API для векторного поиска не должно блокировать работу;
- настройки расписания и репозитория не входят в публичные данные скилла.

## Что уже выяснено об Iva

- `ast-index` подходит для поиска символов, использований, реализаций, вызовов, зависимостей и структуры проекта;
- Iva умеет отправлять rich messages с заголовками, таблицами, кодом и раскрывающимися блоками через встроенный `rich-post`;
- `memory_search` умеет ограничивать поиск поддиректориями vault;
- строгого фильтра памяти по полю `domain` пока нет, поэтому изоляцию следует строить через отдельное пространство каждого репозитория;
- без ключа для эмбеддингов память продолжает работать через BM25;
- плановый запуск нужно регистрировать через механизм расписаний Iva, не реализуя собственный планировщик внутри скилла.

## MVP

Первая рабочая версия должна:

1. Подключать один локальный репозиторий.
2. Индексировать его через `ast-index`.
3. Работать в режимах `daily` и `explain`.
4. Выбирать тему с учётом уже изученного.
5. Создавать одну компактную rich-карточку.
6. Хранить изолированную карту и учебный прогресс.
7. Запускаться вручную и через расписание Iva.
8. Корректно продолжать работу после изменения commit.

## Статус

Проект находится на этапе проектирования MVP.
